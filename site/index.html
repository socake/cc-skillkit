k8s-triage ops-toolkit

Read-only, evidence-first triage of an unhealthy Kubernetes workload. Drives a fixed order — workload → events → logs → scheduling → networking — and reports a named root cause, not a log dump. Encodes the traps that waste the most time: Pending is usually unschedulable not out-of-capacity; the crash is in --previous logs; memory-HPAs over-scale steady-memory services.

Triggers

CrashLoopBackOffPendingOOMKilled ImagePullBackOffstuck rolloutpost-deploy 5xx

Say this in Claude Code

“My pod is in CrashLoopBackOff, help me triage it”

incident-rca ops-toolkit

Methodical root-cause analysis for an incident or regression. Reconstruct the timeline, correlate with recent changes, test multiple hypotheses in parallel under strict evidence discipline (every claim cites a log line, metric, or diff), drill to the mechanism — then emit a root-cause card or a blameless postmortem. The enemy it kills: the plausible-but-wrong first story.

“Do a root cause analysis of last night's outage”

Why a marketplace, not loose skills

Portable

marketplace add socake/cc-skillkit rebuilds everything on a fresh box. No absolute paths.

Versioned & validated

Semver per plugin; CI checks every skill's frontmatter, naming, and manifest on each push.

One-command lifecycle

Install · update · uninstall · enable · disable through the official claude plugin CLI.

Design principles

The reasoning behind the kit — visible in every skill.

  • Evidence before assertion. Every conclusion carries a pointer — a log line, a metric, a timestamp. No bare guesses.
  • Read-only first. Skills that touch infrastructure diagnose without mutating state; they propose the fix, a human applies it.
  • Progressive disclosure. SKILL.md stays lean; heavy playbooks live one level down and load only when relevant.
  • Vendor-neutral. Hard-won lessons survive as general guidance — useful to anyone, tied to no one's internal stack.
  • Quality over count. A coherent, trustworthy set beats a kitchen-sink dump. CI is the gate.
